01

HTML 문서 구조와 텍스트

HTML 문서는 정해진 "기본 틀"로 시작해요. 이 틀이 브라우저에게 "나는 표준 규격을 지키는 한국어 페이지야"라고 알려줍니다.

<!DOCTYPE html>            <!-- "표준 규격" 선언 -->
<html lang="ko">          <!-- 한국어 페이지 -->
  <head>                  <!-- 화면엔 안 보이는 정보(제목·인코딩) -->
    <meta charset="UTF-8">
    <title>페이지 제목</title>
  </head>
  <body> 실제 보이는 내용 </body>
</html>

제목(헤딩)은 "글자 크기"가 아니라 "목차 단계"

h1~h6은 책의 목차 같은 거예요. h1은 책 제목(페이지당 1개), h2는 챕터… 순서대로 씁니다. "글자를 크게 하고 싶어서" h1을 쓰면 안 돼요. 크기는 CSS로 바꿉니다.

strong/em vs b/i — 보긴 같아도 "의미"가 달라요

<strong>·<em>은 "중요/강조"라는 뜻이 담겨 스크린리더가 톤을 다르게 읽어줍니다. <b>·<i>는 그냥 모양만 바꿉니다. 의미가 있으면 strong/em을 쓰세요.

블록 vs 인라인 — 줄을 다 차지하나, 글자만큼만 차지하나

블록 요소(div, p, h1)는 한 줄을 통째로 먹어서 위→아래로 쌓이고, 인라인 요소(span, a, img)는 글자 크기만큼만 차지해 옆으로 붙습니다.

줄바꿈·여백 팁 — 문단은 <p>로 묶고, 문단 사이 간격은 CSS로. <br>을 여러 번 눌러 여백 만들기는 금지예요(주소·시처럼 줄바꿈이 의미일 때만 사용).
02

리스트, 이미지, 링크, 표

리스트 3형제

순서가 없으면 <ul>(점), 있으면 <ol>(번호), '용어 : 설명' 짝이면 <dl>을 씁니다.

이미지와 링크의 필수 매너

  • 이미지엔 alt 필수 — 그림이 안 떠도, 눈이 불편한 분도 내용을 알 수 있게 설명을 적습니다. 순수 장식용이면 alt=""로 비워 리더기가 건너뛰게 해요.
  • 새 창 링크엔 안전장치 — target="_blank"로 새 창을 열 땐 rel="noopener noreferrer"를 꼭 붙입니다(보안).
<img src="cat.jpg" alt="잠자는 고양이">
<a href="https://example.com" target="_blank" rel="noopener noreferrer">새 창으로</a>

표(table) — 칸 합치기와 접근성

표는 표 형태의 데이터에만 씁니다(레이아웃용 금지). 제목칸 th에는 scope를, 칸을 합칠 땐 colspan(가로)·rowspan(세로)을 씁니다.

03

미디어와 시멘틱 마크업

동영상·소리

<video>·<audio>에 controls(재생바), autoplay(자동재생), muted(음소거)를 붙여요. 자막은 안에 <track kind="subtitles">를 넣습니다.

<video src="movie.mp4" controls muted>
  <track src="ko.vtt" kind="subtitles" srclang="ko" label="한국어">
</video>

시멘틱 태그 = div에 "이름표" 붙이기

똑같은 박스라도 <div>는 "무슨 박스인지" 모릅니다. 대신 header(머리말)·nav(메뉴)·main(본문, 딱 하나)·section(주제 구역)·article(독립된 글)·footer(꼬리말)처럼 이름이 있는 태그를 쓰면 검색엔진·스크린리더가 구조를 이해합니다.

section vs article — section은 "주제로 묶은 구역", article은 "그것만 떼어내도 말이 되는 완결된 글"(기사·블로그 글·댓글 하나).

자바스크립트 없이 쓰는 기본 UI

아코디언(details/summary), 진행률(progress), 측정값(meter)은 JS 없이도 동작합니다.

04

웹 폼과 입력 요소

<form>은 사용자가 입력한 값을 서버로 보내는 "데이터 우체통"이에요. action(보낼 주소)과 method(GET/POST)를 정합니다.

입력 타입을 잘 고르면 모바일 키보드가 바뀐다

type을 데이터에 맞게 고르면(email, number, date, password, file, checkbox, radio) 휴대폰에서 알맞은 키보드가 떠요. (checkbox=여러 개, radio=하나만)

label은 클릭 영역을 넓혀주는 친구

<label>의 for와 입력칸의 id를 같게 하면, 글씨만 클릭해도 입력칸이 활성화됩니다. 아래에서 직접 글씨를 눌러보세요.

관련 항목은 fieldset으로 묶기

라디오·체크박스처럼 한 묶음인 항목은 <fieldset>으로 감싸고 <legend>로 그룹 제목을 답니다.

05

CSS 선택자와 우선순위

선택자는 "누구를 꾸밀지" 고르는 방법이에요. 실무에선 재사용하기 좋은 .class를 중심으로 설계합니다(#id는 너무 강하고, 태그명은 너무 광범위).

같은 곳에 색을 여러 번 지정하면, 누가 이길까?

점수가 높은 규칙이 이깁니다: 인라인(1000) > #id(100) > .class(10) > 태그(1). 아래는 한 글자에 3번 색을 줬을 때 id가 이기는 예시예요.

!important는 이 모든 걸 무시하는 "반칙기"예요. 꼬임의 원인이 되니 되도록 쓰지 마세요.

결합자 — 위치로 콕 집기

A > B 바로 아래 자식만 · A B(공백) 모든 자손 · A + B 바로 뒤 형제 · A ~ B 뒤따르는 모든 형제.

가상 클래스 — "이럴 때만" 스타일

:hover(마우스 올림), :focus-visible(탭 키로 이동했을 때만 테두리), :required(필수 입력칸).

06

CSS 텍스트 최적화 (한국어)

줄 간격 line-height

줄 간격은 단위 없는 숫자(1.5~1.8)로 줍니다. 단위를 빼야 글자 크기에 맞춰 비례하고 상속 꼬임이 안 생겨요.

한글 줄바꿈 word-break: keep-all

기본값은 한글을 글자 단위로 어색하게 자릅니다. keep-all을 주면 단어 단위로 끊겨요. (긴 영어/URL이 칸을 뚫는 건 overflow-wrap: break-word로 방지)

말줄임표(…) 공식 — 3개 모두 필요

하나라도 빠지면 작동 안 해요: white-space:nowrap + overflow:hidden + text-overflow:ellipsis.

text-wrap: balance; — 여러 줄 제목의 줄 길이를 자동으로 균형 있게 맞춰줍니다(이 페이지 큰 제목에 적용돼 있어요).
07

배경, 박스, 위치(position)

둥근 모서리·그림자·원 만들기

border-radius로 모서리를 둥글게(50%면 완전한 원), box-shadow로 떠 보이는 입체감을 줍니다.

position — 가장 헷갈리는 부분, 예시로 끝내기

  • relative: 원래 자리를 지키면서 살짝 이동. 주로 absolute 자식의 기준점 역할.
  • absolute: 공중에 떠서, 가장 가까운 relative 부모를 기준으로 배치(예: 카드 우상단 배지).
  • fixed/sticky: 스크롤해도 화면/영역에 고정.

08

Flexbox & Grid

요소를 정렬·배치하는 두 도구예요. Flex는 1차원(한 줄을 가로 또는 세로로), Grid는 2차원(행+열 격자). 한 줄 정렬엔 Flex, 페이지 전체 뼈대엔 Grid가 편합니다.

Flex — 한 줄 정렬의 끝판왕

justify-content=가로 정렬, align-items=세로 정렬. "가운데 정렬"이 한 줄로 끝나요.

Grid — 칸에 이름 붙여 뼈대 만들기

grid-template-areas로 칸에 이름을 적으면, 코드만 봐도 레이아웃이 그림처럼 보입니다.

09

애니메이션과 다단

transform + transition — 부드러운 움직임

transform은 이동(translate)·회전(rotate)·크기(scale)를 담당하고, transition이 그 변화를 "천천히" 만들어 부드럽게 합니다.

@keyframes — 무한 반복 애니메이션

0%→100% 단계별 변화를 정의하고 infinite로 무한 반복. 로딩 스피너가 대표 예시예요.

다단(multi-column) — 신문처럼 여러 단

column-count로 단 수를 정하고, 카드가 단 경계에서 잘리지 않게 break-inside: avoid를 줍니다.

시험에 나올만한 것 — 핵심 정리

자주 나오고 자주 틀리는 것만 모았어요. 시험 직전 이 부분만 훑어도 됩니다.

① 무조건 외우는 규칙

주제정답 포인트
h1 개수페이지당 1개, 숫자 건너뛰기 금지
main 개수문서에 단 하나
이미지 alt필수. 장식용은 alt=""
새 창 링크target="_blank" + rel="noopener noreferrer"
label 연결for ↔ id 일치
line-height단위 없는 숫자(1.5)
th 접근성scope="col"/"row"
칸 합치기가로 colspan / 세로 rowspan

② 명시도(우선순위) 순서 — 단골 출제

!important > 인라인(1000) > #id(100) > .class·가상클래스(10) > 태그(1) > *(0)

③ 헷갈리는 짝 비교

strong vs b

strong=의미상 강조(접근성), b=단순 굵게

em vs i

em=의미상 강조, i=단순 기울임

Flex vs Grid

Flex=1차원(한 방향), Grid=2차원(행+열)

relative vs absolute

relative=자리 유지·기준점, absolute=relative 부모 기준 띄움

section vs article

section=주제 구역, article=떼어내도 완결된 글

> vs (공백)

>=직계 자식만, 공백=모든 자손

④ 자주 틀리는 함정

  • 헤딩을 글자 크기 용도로 쓰기 → 금지(크기는 CSS)
  • <br> 연타로 여백 만들기 → 금지(여백은 CSS)
  • 표를 레이아웃용으로 쓰기 → 금지(데이터 전용)
  • 말줄임표 3종 세트 중 하나 누락 → 작동 안 함
  • line-height: 24px처럼 단위 붙이기 → 상속 꼬임
  • 다단에서 카드 잘림 → break-inside: avoid; 누락
